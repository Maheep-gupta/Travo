| D-027 | 2026-11-12 | **Session transition model (spec 4.2, G24).** `decideTransition` in `packages/domain/src/transitions.ts` is the one rule set:<br>• An observation older than the recorded one is ignored; an equal time is applied, as the v3 write guard does.<br>• The same status again is `unchanged`, never a transition.<br>• An unreadable or partial read is no evidence. Absence from a complete read ends a session (never completes it).<br>• `unknown` is lost evidence: the last known status is kept, so X → unknown → X is not a transition (`evidence_regained`). Same activity time, or none, raises nothing.<br>• No status pair is forbidden. Completed/failed → active is a restart (only the source can report one); needs approval → anything else needs a read from a trusted source that isn't older.<br>• `detectAlerts` orders by the row's server-set `updated_at`. The connector keeps relying on the write guard for ordering (events only for kept rows), so `connector.ts` is unchanged. | Sources are polled, so intermediate states are missed; refusing a reported status would show a stale one as current.
